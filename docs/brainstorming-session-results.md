## 执行摘要

**主题:** AI 提示词分析工具 MVP 设计

**会议目标:** 设计一套 AI CLI 脚手架，找到当前项目里面所有包含提示词的文件，并把提示词内容输出出来

**使用的技术:** First Principles Thinking + Resource Constraints

**产生的总想法数:** 8个核心技术决策

### 识别的关键主题:
- 简化优先的 MVP 方法论
- 基于 AI 判断的智能识别策略
- 成本效益优化的技术架构
- 以提示词为维度的数据结构设计

## 技术会议

### First Principles Thinking + Resource Constraints - 45分钟

**描述:** 通过基础原理分解和资源约束来聚焦最简可行的技术方案

**产生的想法:**
1. 提示词定义：提供给大语言模型去完成某个目标的文本内容
2. 识别策略：使用 AI API 调用进行智能判断
3. 提取目标：只需要提取属于提示词的内容部分
4. 预筛选策略：先用简单规则筛选文本文件类型
5. 误判容忍：MVP 阶段完全可以接受误判
6. 输出格式：JSON 文件存储所有发现的提示词
7. 位置定位：以行号范围标注提示词在文件中的位置
8. 数据维度：以提示词为维度而非文件为维度

**发现的洞察:**
- 在资源约束下，"预筛选 + AI 验证"比"纯 AI 判断"更经济高效
- MVP 阶段接受适度误判，可以大大简化实现复杂度
- 以提示词为维度让数据更加原子化，便于后续分析和对比
- 行级定位已经能满足基本的追溯需求

**显著的连接:**
- TDD 方法论与简化架构的完美结合
- Node.js CLI + Qwen 模型为快速原型开发提供良好基础
- 资源约束驱动的技术选型与 MVP 理念高度一致

## 想法分类

### 即时机会
*现在就可以实现的想法*

1. **文件预筛选机制**
   - 描述: 递归扫描目录，只保留文本文件类型 (.md, .txt, .js, .py, .yaml, .json)
   - 为什么是即时的: 使用标准的 Node.js fs 模块，无需外部依赖
   - 所需资源: 15分钟开发时间

2. **简化的 JSON 输出格式**
   - 描述: 设计包含 id、content、file、startLine、endLine、confidence、type 的数据结构
   - 为什么是即时的: 标准 JSON 格式，无复杂处理逻辑
   - 所需资源: 数据结构设计，10分钟

3. **基础的 AI API 集成**
   - 描述: 集成 Qwen API 进行文件内容的提示词识别
   - 为什么是即时的: 标准的 HTTP API 调用，有现成的 SDK
   - 所需资源: API 密钥和基础网络请求代码

### 未来创新
*需要开发/研究的想法*

1. **智能的提示词类型识别**
   - 描述: 自动区分 system_prompt、user_prompt、few_shot_example 等不同类型
   - 需要的开发: AI 模型的提示词工程优化，更复杂的分类逻辑
   - 时间线估计: 2-3周的迭代优化

2. **提示词质量评分系统**
   - 描述: 基于多个维度对提示词质量进行自动评分和排序
   - 需要的开发: 评分算法设计，多维度指标体系
   - 时间线估计: 4-6周的研究和开发

### 登月计划
*雄心勃勃的变革性概念*

1. **提示词模式库构建**
   - 描述: 自动识别和分类不同的提示词设计模式，构建可复用的模式库
   - 变革潜力: 能够帮助整个社区学习和应用最佳提示词实践
   - 需要克服的挑战: 大规模数据处理，模式识别算法，社区生态建设

### 洞察与学习
- **简化胜过复杂**: 在 MVP 阶段，简单可行的方案比完美但复杂的方案更有价值
- **AI 驱动的识别**: 使用 AI 来识别 AI 内容是一个自然且高效的选择
- **数据结构的重要性**: 正确的数据维度选择（提示词维度vs文件维度）直接影响后续分析的便利性
- **成本效益权衡**: 预筛选机制可以显著减少 API 调用成本而不影响核心功能

## 行动计划

### 前3个优先想法

#### #1 优先级: 文件扫描和预筛选机制
- 理由: 这是整个工作流的基础，必须首先实现
- 下一步: 编写递归文件扫描代码，实现文件类型过滤
- 所需资源: Node.js fs 模块，15分钟开发时间
- 时间线: 立即开始，1小时内完成

#### #2 优先级: AI 提示词识别和提取
- 理由: 这是核心的智能识别功能，直接决定工具的有效性
- 下一步: 集成 Qwen API，设计提示词识别的 prompt
- 所需资源: Qwen API 密钥，HTTP 客户端库
- 时间线: 1-2小时内完成基础版本

#### #3 优先级: JSON 输出和位置标注
- 理由: 完整的数据输出是 MVP 的最终交付物
- 下一步: 实现精确的行号定位，构建最终的 JSON 输出
- 所需资源: 字符串处理逻辑，JSON 序列化
- 时间线: 30分钟内完成
