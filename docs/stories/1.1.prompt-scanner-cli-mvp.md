# Story 1.1: 提示词扫描CLI工具MVP

## Status
Draft

## Story

**As a** 正在学习提示词工程的开发者,
**I want** 一个能够自动扫描代码库并提取其中所有提示词内容的CLI工具,
**so that** 我可以在5分钟内获得一个项目中所有提示词的清单，快速学习其他项目的提示词设计模式。

## Acceptance Criteria

1. **文件扫描功能**: 工具能够递归遍历指定目录，识别并处理文本文件类型（.md, .txt, .js, .py, .yaml, .json）
2. **AI智能识别**: 调用Qwen API判断文件是否包含提示词内容，并准确提取提示词文本（准确率>70%）
3. **位置标记**: 记录每个发现的提示词在原文件中的大概行号范围，便于后续查找
4. **结构化输出**: 生成包含提示词内容、文件路径、位置信息的JSON格式输出文件
5. **基础CLI接口**: 支持 `node scan.js <directory>` 命令格式，能够处理命令行参数
6. **错误处理**: 遇到文件读取错误或API调用失败时不崩溃，能够继续处理其他文件
7. **性能要求**: 单个中等规模项目（50-100个文件）扫描时间控制在3分钟以内
8. **输出可读性**: 生成的JSON文件结构清晰，包含必要的元数据信息，便于用户直接阅读和理解

## Dev Notes

### 项目背景和技术约束

**基于brief.md和brainstorming-session-results.md的技术决策：**

- **核心技术栈**: Node.js 18+，使用标准库（fs、path），最小化外部依赖
- **AI集成**: Qwen API via HTTP调用，需要API密钥环境变量配置
- **架构原则**: 单文件脚本（scan.js），避免复杂的模块分割
- **数据维度**: 以提示词为维度而非文件为维度，便于后续分析

### 核心实现策略

**三步处理流程（来自技术头脑风暴）:**
1. **智能预筛选**: 先用简单规则筛选文本文件类型，减少API调用成本
2. **AI验证**: 对预筛选的文件调用Qwen API进行提示词识别
3. **结构化输出**: 将识别结果组织为JSON格式

### 数据结构设计

**JSON输出格式（基于头脑风暴设计）:**
```json
{
  "scanMetadata": {
    "scanDate": "ISO timestamp",
    "directory": "扫描目录路径",
    "filesScanned": "扫描文件总数",
    "promptsFound": "发现提示词总数"
  },
  "prompts": [
    {
      "id": "唯一标识符",
      "content": "提示词完整内容",
      "file": "相对文件路径",
      "startLine": "起始行号",
      "endLine": "结束行号",
      "confidence": "AI识别置信度",
      "type": "提示词类型（如system_prompt, user_prompt等）"
    }
  ]
}
```

### 关键技术考虑

- **误判容忍**: MVP阶段接受70%准确率，避免复杂的精确识别逻辑
- **成本控制**: 预筛选机制显著减少API调用，控制使用成本
- **错误隔离**: 单个文件处理失败不应影响整体扫描进程
- **环境兼容**: 支持Windows/macOS/Linux跨平台运行

### 安全和合规要求

- API密钥通过环境变量配置，不硬编码
- 只读文件系统访问，不修改用户代码
- 不上传用户代码内容到外部服务
